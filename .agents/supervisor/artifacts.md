# Результаты агентов

Каждый агент завершает поручение Markdown-отчётом с YAML frontmatter. Смотритель заранее назначает файл `.agents/project/sessions/<run>/results/<task>-<role>-<attempt>.md`. Итог смотрителя использует тот же формат; ТЗ, задачи, поручения и checkpoint остаются самостоятельными документами и связываются с отчётом через пути.

Единственный источник структуры заголовка — [JSON Schema](schemas/agent-result.schema.json). Шаблон отчёта хранится у каждой роли в `templates/report.md`. Подставь фактические значения вместо `<...>`; шаблоны сами по себе не являются результатами работы и не проверяются как отчёты. Старые отчёты без заголовка сохраняются; автоматический сбор читает только явно переданные отчёты и каталог `results/` выбранной сессии.

## Поля

| Поле | Назначение |
| --- | --- |
| `schema_version`, `kind` | Версия контракта и тип документа: `1`, `agent-result` |
| `role` | Исполнитель: supervisor, spec-writer, developer, tester, reviewer |
| `task` | Путь к существующей задаче от корня проекта; `null` у составителя/смотрителя до согласования и публикации задач |
| `run` | Имя каталога сессии; должно совпадать с расположением отчёта |
| `attempt` | Сохранённый цикл исправлений из checkpoint: начальный 0, исправления 1–3 |
| `result` | Итог поручения: pass, fail или blocked; это отдельное понятие от статуса задачи |
| `revision` | Git commit, наличие изменений в проверяемом срезе (`dirty`) и пути файлов evidence |
| `checks` | Выполненные или заблокированные проверки, результаты, команды/exit codes и причины |
| `artifacts` | Существующие файлы результата: ТЗ, изменённые исходники/тесты, логи; пути от корня проекта |

Пути записываются с `/`. `revision.evidence` при `dirty: true` содержит снимок проверяемых файлов, patch или файл с SHA256 по действующим правилам проверки. Результат не может ссылаться на отсутствующий файл. До записи отчёта создай перечисленные evidence и артефакты; собственный отчёт в `artifacts` включать не требуется.

`checks` содержит хотя бы одну проверку, включая содержательную ручную проверку для документации. Общий результат сворачивается из checks: любой fail даёт fail, иначе любой blocked даёт blocked, иначе pass. Для командной проверки pass обязателен `exit_code: 0`. Для blocked укажи `reason`; для ручной проверки команда и exit code не обязательны. Успешное составление проекта ТЗ означает выполнение поручения, подтверждение требований пользователем фиксирует смотритель отдельно.

## Команды из корня

```powershell
pnpm agents:check .agents/project/sessions/<run>
pnpm agents:check .agents/project/sessions/<run>/results/<report>.md
pnpm agents:summary .agents/project/sessions/<run>
pnpm agents:summary .agents/project/sessions/<run> --output .agents/project/sessions/<run>/summary.yaml
pnpm agents:test
```

Для сессии читаются только `results/*.md`: черновики, поручения и прежние отчёты не захватываются. Можно передать несколько отчётов или сессий. Ошибочный отчёт внутри `results/` отклоняет весь сбор; пустой набор также является ошибкой. Повтор сочетания run/task/role/attempt в разных отчётах отклоняется, исправление в той же попытке обновляет назначенный файл.

`agents:check` возвращает exit 0 для структурно корректных отчётов, включая честно описанные fail и blocked. Неверная схема, противоречивый итог и сломанная ссылка дают exit 1. Подлинность выполнения команд, содержимое evidence и актуальность версии проверяет смотритель перед приёмкой.

Сводка показывает реальный `task_status` из файла задачи и последнюю попытку каждой роли из enum JSON Schema. Отсутствующие роли перечисляются в `missing_roles`, их результат — `null`; прежняя история с четырьмя ролями остаётся читаемой. Для intake без задачи `task` и `task_status` равны `null`. Состав исполнителей задаётся процессом: для реализации обязательны tester и reviewer. Валидатор и сводка проверяют данные, решение о статусе смотритель публикует на основании их актуальных заключений.

Без `--output` сводка печатается в stdout. Запись разрешена только в `.agents/project/sessions/<run>/summary.yaml` для одной сессии; существующий файл заменяется только если он уже является сводкой этого инструмента. Статусы задач, ТЗ и исходные отчёты сборщик не изменяет. После приёмки смотритель синхронизирует задачу/индекс и пересобирает сводку, чтобы отразить свежий статус.

Для разбора используется [yaml](https://eemeli.org/yaml/), для схемы — [Ajv](https://ajv.js.org/guide/getting-started.html). YAML-заголовок должен начинаться с отдельной строки `---`, заканчиваться такой же строкой и сопровождаться непустым Markdown-текстом. Неизвестные поля и повторные YAML-ключи отвергаются.
