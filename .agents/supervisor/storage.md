# Хранение рабочих материалов

Общие материалы команды находятся в локальной, игнорируемой Git папке `projects/`. Вход для человека — `projects/tasks_list.md`; ссылка каждой работы ведёт в её README. Настройки, инструкции и инструменты агентов хранятся в `.agents/<role>/`. Исходники, тесты и публичная документация проекта размещаются по архитектуре репозитория.

## Структура

```text
projects/
  tasks_list.md
  solution.md
  backlog.md
  tasks/<work>/
    README.md
    user.md
    specs/
    plans/
    work-items/
    sessions/<run>/
    backups/
```

Создавай подкаталоги по мере надобности. `<work>` обозначает конечную работу и собирает её документы вместе. Не создавай общий `projects/user/` или общий каталог сессий.

## Аудитория и назначение документа

README — вход: цель, статус, итог и ссылки на имеющиеся материалы. `user.md` объясняет результат понятным языком, спецификация задаёт технический контракт, план — способ исполнения согласованного решения, work-items — отдельные задания, критерии и проверки. Не дублируй требования спецификации в README.

`tasks_list.md` ведёт к README каждой работы и кратко показывает доступность и состояние, например «можно брать», «нужно согласовать», «ожидает зависимость», «в работе», «завершено». Готовность — отдельная отметка, а не новый task-status. Сохраняй `todo`, `in-progress`, `done`, `blocked`; supervisor синхронно обновляет статус в файле work-item и списке. Черновик остаётся недоступным для реализации до согласования требований и закрытия зависимостей.

Постоянные решения и ограничения хранятся в `projects/solution.md`, известные проблемы — в `projects/backlog.md`. Перед закрытием supervisor переносит туда смысл принятых решений и нерешённые проблемы, обновляет README и общие ссылки. Папка `done` не удаляется автоматически. Удаление архивной папки выполняется по запросу пользователя после сохранения постоянной памяти и обновления ссылок.

Новые отчёты с YAML находятся в `projects/tasks/<work>/sessions/<run>/results/`; checkpoint — в `state.md`, сводка — в `summary.yaml`, черновики — в `drafts/`, логи и снимки — в `evidence/`, временные стенды — в `repro/`. Сессия принадлежит одной работе. Общему исследованию назначай отдельную завершённую работу или разделяй материалы по владельцам с явным provenance.

Механическая миграция старого отчёта не меняет его результат, попытку, версию, usage или смысл; прежний hash свидетельствует только о прежнем срезе. Рабочие деревья Git перемещаются командами Git. Не включай tracked `.git`, symlinks вне дерева и чужие изменения в ручные переносы.

При согласованной очистке или переносе сохраняй назначенные актуальные задачи, исходные отчёты и snapshot/evidence, нужные для их provenance; не обещай сохранность логов внешних workflow, которой проект не контролирует.

Пути временного документа или вывода скилла направляй в папку текущей работы или её сессию. Установленные скиллы для этого не меняй. Штатные outputs генераторов и test runners сохраняют пути из конфигурации; нужные доказательства связывай с отчётом или копируй в evidence. Явный путь пользователя имеет приоритет.

`docs/_drafts/` остаётся архивом для чтения. Его перенос, изменение или очистка требуют прямого запроса пользователя.
