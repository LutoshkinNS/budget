# Хранение рабочих материалов

Все новые рабочие материалы команды сохраняются в игнорируемом `.agents/project/`. Инструкции, шаблоны и инструменты ролей принадлежат `.agents/<role>/`; постоянные исходники, тесты и публичная документация проекта размещаются по архитектуре репозитория.

## Карта каталогов

| Материал | Путь внутри `.agents/project/` |
| --- | --- |
| Согласованные ТЗ | `specs/<feature>.md` |
| Задачи и индекс | `tasks/<feature>/<task>.md`, `tasks/tasks_list.md` |
| Планы | `plans/<feature>/` |
| Исследования | `research/<topic>/` |
| Общие решения и известные проблемы | `solution.md`, `backlog.md` |
| Поручения | `sessions/<run>/assignments/` |
| Ролевые Markdown-отчёты с YAML | `sessions/<run>/results/` |
| Checkpoint и сводка | `sessions/<run>/state.md`, `sessions/<run>/summary.yaml` |
| Черновики до согласования | `sessions/<run>/drafts/` |
| Логи, скриншоты, traces, patches и снимки SHA256 | `sessions/<run>/evidence/` |
| Копии проекта и временные стенды воспроизведения | `sessions/<run>/repro/<name>/` |
| Резервные копии данных | `backups/<feature>/<date>/` |
| Изолированные рабочие деревья | `worktrees/` |

Используй kebab-case для новых имён; `<run>` содержит дату и короткое название работы. Создавай каталоги по мере необходимости. Смотритель назначает файлы результатов и владельцев до делегирования по [процессу команды](workflow.md).

## Применение к скиллам и инструментам

Путь временного документа, плана или отчёта, указанный в скилле, заменяется соответствующим путём из таблицы. Это относится к локальным и глобальным скиллам, в том числе предлагающим писать в `docs/_drafts/`, `docs/plans/`, `docs/superpowers/`, корневые `research/` или `.codex/`. Адаптируй путь в поручении; установленные скиллы ради такой замены редактировать не требуется. Точки подключения Codex и указатели остаются в `.codex/` по корневому AGENTS.md.

Для логов и browser output, путь которых выбирает агент, указывай каталог evidence текущей сессии. Файлы, автоматически создаваемые приложением, генератором или test runner по конфигурации проекта, сохраняют штатные пути; нужные доказательства копируются в evidence либо явно связываются с отчётом. Копии проекта и временные сборочные стенды размещаются в repro. Активные зарегистрированные worktree перемещаются только через Git.

## Архив и приоритет пользователя

`docs/_drafts/` используется для чтения прежних материалов. Новые файлы, изменения существующих, перенос и удаление содержимого архива выполняются только по прямому указанию пользователя. Исторические ссылки на архив сохраняются: правило задаёт место для новой работы, а разбор старой истории является отдельным поручением.

Если пользователь явно назначил иной путь, следуй этому указанию и зафиксируй исключение в поручении и отчёте. Перед завершением смотритель проверяет новые пути в изменениях и отчётах. `agents:check` проверяет ролевые отчёты; соблюдение правил для остальных рабочих файлов контролируется смотрителем при приёмке.
