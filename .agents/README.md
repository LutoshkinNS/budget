# Команда разработки Budget

Смотритель ведёт основной диалог и управляет четырьмя ролями: составителем ТЗ, разработчиком, тестировщиком и ревьюером. Каждая роль хранит инструкции и вспомогательные материалы в отдельном каталоге. Смотритель распределяет работу и передаёт результаты; архитектуру и соответствие ТЗ проверяет независимый ревьюер.

| Роль | Точка входа | Материалы |
| --- | --- | --- |
| Смотритель | [supervisor/instructions.md](supervisor/instructions.md) | [Процесс](supervisor/workflow.md), [поручение](supervisor/templates/assignment.md), [состояние](supervisor/templates/state.md) |
| Составитель ТЗ | [spec-writer/instructions.md](spec-writer/instructions.md) | [ТЗ](spec-writer/templates/spec.md), [задача](spec-writer/templates/task.md) |
| Разработчик | [developer/instructions.md](developer/instructions.md) | Правила реализации и передачи результата |
| Тестировщик | [tester/instructions.md](tester/instructions.md) | [Отчёт проверки](tester/templates/report.md) |
| Ревьюер | [reviewer/instructions.md](reviewer/instructions.md) | [Чеклист](reviewer/review-checklist.md), [отчёт](reviewer/templates/report.md) |

Результат каждой роли — Markdown-отчёт с YAML-метаданными. [Формат и команды проверки/сводки](supervisor/artifacts.md) задают общий контракт. Код, тесты, ТЗ и другие файлы перечисляются в отчёте как артефакты; статусы задач обновляет смотритель.

Все новые рабочие материалы размещаются по [правилам хранения](supervisor/storage.md). Они применяются также к путям из установленных скиллов; `docs/_drafts/` используется как архив прежней работы.

Общий список находится в [`projects/tasks_list.md`](../projects/tasks_list.md). Он ведёт к README конечной работы, где собраны понятное описание, спецификации, планы, work-items и сессии. Постоянные решения и backlog хранятся в `projects/solution.md` и `projects/backlog.md`. При первом запуске на новой копии проекта смотритель создаёт отсутствующие рабочие документы по необходимости.

## Библиотека скиллов

Общие скиллы находятся в `.agents/skills/`; инструкции каждой роли содержат карту их применения. Уникальные ролевые скиллы при появлении хранятся в `.agents/<role>/skills/` и подключаются через символическую ссылку в общей библиотеке. [Правила выбора и подключения](supervisor/skills.md) сохраняют единственный исходный экземпляр и ограничения роли. Существующие скиллы ради новой карты не перемещаются.

## Запуск работы

Открой проект в Codex и начни новый диалог. Корневой `AGENTS.md` назначает основному агенту роль смотрителя. Например:

> Хочу добавить бюджет категории. Подготовь с составителем ТЗ решение для согласования.

> Реализуй согласованные задачи из projects/tasks/category-budget/ с разработчиком и тестировщиком.

В [экономном профиле](supervisor/models.md) developer использует `gpt-6-luna/high`, остальные роли — `gpt-6.1-sol/high`. Перед реализацией составитель готовит задачу по [критериям готовности](spec-writer/task-readiness.md). Тестировщик и ревьюер получают один финальный срез изменений. Одновременно допускаются три субагента; число ролей не обязывает запускать их все для каждого запроса. Политика доступа наследуется от основной сессии: границы изменения файлов в инструкциях являются рабочим соглашением, а не отдельной песочницей.

## Подключение Codex

Codex обнаруживает проектные роли через `.codex/agents/*.toml`. Эти файлы содержат имя роли, описание, модель и указатели на инструкции. `.codex/config.toml` содержит локальные настройки сессии. После изменения конфигурации начни новую сессию, чтобы обнаружить роли.

На новой копии проекта создай `.codex/agents/` и по одному TOML-файлу для `spec-writer`, `developer`, `tester`, `reviewer`. Модель подставь по таблице профиля:

```toml
name = "<role>"
description = "<когда использовать роль>"
model = "<модель роли>"
model_reasoning_effort = "high"
developer_instructions = """
Твоя роль — <role>. Прочитай AGENTS.md, .agents/<role>/instructions.md
и .agents/supervisor/workflow.md. Выполни поручение смотрителя в выданных границах.
"""
```

Для ограничения параллелизма добавь в `.codex/config.toml`:

```toml
model = "gpt-6.1-sol"
model_reasoning_effort = "high"

[agents]
enabled = true
max_threads = 3
max_depth = 1
```

В уже открытой сессии используй fallback по [правилам выбора моделей](supervisor/models.md): инструкции и явные параметры роли передаются встроенному `worker`, замена фиксируется в отчёте.

Описание точек подключения: [официальная документация Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents).
